# Политика безопасности

## Поддерживаемые версии

Исправления безопасности выходят только для последней мажорной ветки скрипта.
Более старые версии не поддерживаются — обнови `deploy-remnanode.sh` до
актуальной версии.

| Версия | Поддержка          |
|--------|--------------------|
| 3.10.x | ✅ поддерживается   |
| < 3.10 | ❌ не поддерживается |

> **Ноды, развёрнутые версиями до 3.10, требуют вмешательства.** В них
> приватные сети в Config Profile отправлены в `DIRECT`, то есть нода идёт по
> адресу, который ей назвал клиент, — включая cloud-metadata хостера и
> собственный API в обход UFW. Правится в панели (см. ниже), а остальное
> накатывается скриптом `update-node.sh` из этого репозитория. Проверить
> состояние ноды: `sudo bash check-node.sh`.

## Как сообщить об уязвимости

**Не открывай публичный issue и не описывай уязвимость в PR.** Публичное
раскрытие до выпуска фикса подвергает риску всех, кто уже развернул ноду.

Используй один из приватных каналов:

1. **GitHub Security Advisories** (предпочтительно) — вкладка **Security →
   Report a vulnerability** в этом репозитории. Канал приватный, виден только
   мейнтейнерам.
2. **Telegram** — [@anfixit](https://t.me/anfixit) (замени на свой контакт,
   если публикуешь форк).

В сообщении по возможности укажи:

- версию скрипта (`SCRIPT_VERSION` в шапке) и версию Ubuntu;
- затронутый компонент (фаза скрипта, генерируемый конфиг nginx/Xray, cron,
  UFW и т. п.);
- шаги воспроизведения и потенциальное воздействие;
- предлагаемое исправление, если есть.

## Сроки реакции

- **Подтверждение получения** — в течение 72 часов.
- **Первичная оценка** — в течение 7 дней.
- **Выпуск фикса** — по согласованию, обычно до 30 дней в зависимости от
  сложности. Уязвимости, ведущие к компрометации ноды или утечке приватного
  ключа Reality, приоритетны.

Мы придерживаемся **скоординированного раскрытия**: детали публикуются после
выхода исправления и разумного окна на обновление.

## Область действия

**В области действия** — код этого репозитория:

- `deploy-remnanode.sh`, `update-node.sh`, `check-node.sh`;
- генерируемые ими конфигурации (sshd, nginx, UFW, sysctl, cron, docker
  compose, Config Profile Xray, watchdog);
- обращение с секретами (приватный ключ Reality, `SECRET_KEY`, права на файлы);
- то, до чего нода позволяет дотянуться клиенту (маршрутизация Xray, доступ к
  внутренним и служебным сетям, изоляция управляющих портов).

**Вне области действия** — уязвимости вышестоящих проектов, о которых следует
сообщать их авторам:

- [Remnawave Panel / Node](https://github.com/remnawave)
- [XTLS/Xray-core](https://github.com/XTLS/Xray-core)
- [henrygd/beszel](https://github.com/henrygd/beszel)
- пакеты Ubuntu, Docker, certbot, fail2ban

## Замечания по безопасной эксплуатации

- Всегда проверяй доступ по SSH **из отдельного терминала** до выхода из
  текущей сессии — фаза хардинга меняет порт и политику аутентификации.
  Начиная с 3.10 скрипт останавливается и ждёт подтверждения сам, но порт
  случайный на каждую ноду, поэтому веди реестр: он в
  `/opt/remnanode/node-info.txt`.
- Приватный ключ Reality хранится в `/opt/remnanode/keys.txt` (`chmod 600`).
  Не коммить его и не пересылай в открытых каналах. Там же лежат `shortId` —
  файл является источником истины для идемпотентного ре-запуска, при его потере
  профиль в панели и на ноде разойдутся.
- **Config Profile — источник истины в панели, а не на ноде.** Правки
  маршрутизации (блокировка приватных сетей, `sniffing.routeOnly`) применяются
  в панели; копия в `/opt/remnanode/config-profile.json` нужна только для
  сверки. `check-node.sh` проверяет именно копию и потому может отставать от
  реальности — доверяй панели.
- При смене IP панели нода теряет **управление**, но не VPN: Xray работает по
  своему конфигу. Не паникуй и не пересобирай ноду — достаточно обновить
  правило UFW для порта `2222`.
- Скрипты запускаются из-под root и подтягивают внешние ресурсы (образы Docker,
  пакеты Docker из официального apt-репозитория с GPG-подписью). Запускай их
  только на доверенных серверах и проверяй источник перед `bash <(wget …)`.
